# Respawn MVP v1 — proposed assumptions

These assumptions belong to the new attached MVP brief. They are not implemented changes yet.

- The final product name is Respawn.
- The new scope supersedes AI, payment and multi-subject work. Recovery is free.
- The requested React/TypeScript/Vite/Tailwind frontend replaces the old classic-script architecture; data and visual ideas are reused.
- Unknown hiring dates use a clearly provisional 14-day window. Month/range estimates use the earlier first-of-month boundary.
- Daily buffer starts at 10%; absent durations start at easy 25 / medium 45 / hard 70 minutes.
- Only explicitly familiar basics get Refresh estimates. Confidence does not mark completion.
- Existing bank IDs/titles are preserved. Original problem URLs are missing and will not be invented.
- Striver sample records are disabled for real scheduling until verified data is supplied.
- Other-subject activities and company-specific claims are out of scope.
- Pod membership includes the creator in the maximum of five. Member status is based on recorded study activity, not opening a page.
- The default reminder proposal is opt-in email through Supabase scheduling plus a configured provider; absent configuration is shown honestly.
- Old preparc_* database objects remain until an additive import is reviewed. No production data is reset.
- This phase stops at the proposal because Part G of the user's attachment explicitly requests approval before implementation.
